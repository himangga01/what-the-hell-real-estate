# 개인정보·로그 정책

**적용 범위**: 공개 API, 관리자 API, 수집기, 웹 앱, 분석·오류·감사 로그  
**기본값**: 개인 시나리오 무저장

## 목적

주소, 보유주택, 거래일과 금액을 조합하면 개인의 경제 상황을 추정할 수 있다.
법적 민감정보 분류 여부와 무관하게 제품에서는 민감한 재무 시나리오로 취급한다.
서비스에 필요하지 않은 식별정보를 받지 않고, 분석 요청을 기본 영구 저장하지 않는다.

## 받지 않는 정보

- 주민등록번호·외국인등록번호
- 등기번호·등기필정보
- 세대원 실명, 전화번호와 이메일
- 계좌번호·카드번호
- 원문 계약서·등기부 전체 파일
- 정확한 생년월일; 필요하면 세금 사건일의 만 나이만 입력

API 스키마에 위 필드를 만들지 않으며 알려지지 않은 요청 필드는 거부한다.

## 요청 데이터 수명

```text
브라우저 입력
→ TLS 요청
→ 메모리 내 검증·정규화·규칙 평가
→ 응답 생성
→ 요청 본문과 중간 시나리오 폐기
```

- v1은 사용자 계정과 저장 시나리오 기능을 제공하지 않는다.
- 서버 세션, 작업 큐, 추적 도구와 예외 리포터에 요청 본문을 넣지 않는다.
- 프런트의 새로고침 복원은 기본적으로 메모리 상태만 사용한다.
- 브라우저 로컬 저장을 추가하려면 명시적 선택, 만료, 전체 삭제와 기기 공유 경고가 필요하다.

## 로그 허용 목록

운영 로그에는 다음만 허용한다.

- 무작위 요청 ID
- 라우트 템플릿과 HTTP 상태
- 소요 시간·타임아웃·재시도 횟수
- 결과 상태와 오류 사유 코드
- 규칙 번들·엔진 버전·추적 해시
- 출처 레지스트리 ID와 수집 결과 상태
- 관리자 대상 ID, 결정, 승인자 ID와 시각

다음은 금지한다.

- 원문·정규화 주소, PNU 전체 값과 좌표
- 가격, 공시가격, 비용, 지분과 보유 목록
- 세대 구성과 나이
- 질문 원문과 생성형 답변 원문
- 정부 문서 전문 또는 RAG 프롬프트 전체
- 인증 토큰·쿠키·API 키

필요한 집계는 요청 경로에서 범주값으로 변환한다. 예를 들어 주소 대신 시도 코드의
비식별 집계만 사용하며, 희소 범주는 최소 집계 기준을 충족할 때만 노출한다.

## 오류와 추적

- 프레임워크 요청 본문 로깅을 끈다.
- validation error는 JSON 경로와 오류 코드만 남기고 거부된 값을 남기지 않는다.
- 예외 추적 도구에는 헤더·본문·로컬 변수를 기본 차단하는 before-send 필터를 둔다.
- DB 느린 쿼리 로그에는 바인드 값이 포함되지 않게 한다.
- 생성 모델 공급자에게 개인 시나리오를 보내지 않는다. RAG 질문도 개인 사실을 제거한다.
- 비밀 값은 시작 시 허용 목록으로 로드하고 설정 덤프·헬스 응답에 표시하지 않는다.

## 관리자·감사 로그

법적 데이터 게시 감사에는 개인 시나리오가 아니라 다음을 장기 보존한다.

- 원문·스냅샷·규칙·번들의 해시
- 변경 전후 대상 ID
- 검수자·게시자 ID, 시각, 이유
- 골든 테스트 실행 ID와 결과
- 접근 권한 변경과 실패한 게시 시도

검수자 실명 대신 내부 계정 ID를 사용하고 접근은 최소 권한으로 제한한다.

## 보존 기간 초안

| 데이터 | 기본 기간 | 비고 |
|---|---:|---|
| 공개 API 접근 로그 | 30일 | 허용 목록 필드만 |
| 애플리케이션 오류 로그 | 30일 | 입력값 제거 |
| 보안 이벤트 | 1년 | 본문·시나리오 없음 |
| 관리자 게시 감사 | 서비스 존속 기간 | 규칙 재현 목적 |
| 정부 원문 스냅샷 | 권리·법적 정책에 따름 | 공개 노출과 내부 보존 분리 |
| 개인 시나리오 | 0일 | 응답 후 폐기 |

실제 운영 전 개인정보 처리방침, 국내 관련 법령 검토, 공급자별 보존 정책과
침해 대응 절차를 별도 승인한다.

## 보안 테스트

- 금지 필드를 보낸 요청이 422로 거부되는지 검사
- validation·500·timeout 로그에 주소·금액 fixture가 없는지 검사
- 프런트 localStorage·sessionStorage·URL에 시나리오가 없는지 검사
- 생성 모델 요청에 개인 시나리오 필드가 없는지 검사
- 관리자 감사에는 번들·대상 해시와 승인 정보가 있는지 검사
- 로그 내 토큰·쿠키·API 키 패턴 스캔
- 보존 기간이 지난 로그 삭제 작업의 dry-run과 실제 삭제 검증
